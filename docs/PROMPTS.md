# PROMPTS.md — プロンプト設計ドキュメント

> **プロジェクト:** 大学講義 音声ノートAI  
> **作成日:** 2026-05-17  
> **対象ファイル:** `gemini.js` 内 `_buildPrompt()` 関数

---

## 概要

このドキュメントでは、Gemini APIに送信するプロンプトの設計思想・最終形・改善履歴を記録します。  
プロンプトを変更したい場合は `gemini.js` の `_buildPrompt()` 関数を編集してください。

---

## 1. 最終プロンプト（フェーズ3時点）

以下が現在 `_buildPrompt(lectureName)` で生成するプロンプトです。

````
あなたは大学講義の音声を分析する専門AIです。
添付された講義音声ファイルを正確に分析し、以下の指示に従ってJSON形式のみで回答してください。

講義名: 「{lectureName}」   ← 入力がある場合。なければ「不明」

【出力形式】
以下のJSONキーを含む有効なJSONオブジェクトのみを出力してください。
前後の説明文やマークダウンコードブロック（```json など）は絶対に含めないでください。

{
  "transcription": "音声の文字起こし全文。話し言葉をそのまま書き起こすこと。省略しないこと。",
  "summary": "1文目：講義全体の主題。\n2文目：最も重要な概念または議論。\n3文目：結論や次回への展望。",
  "keyPoints": [
    "重要ポイント1（具体的・簡潔に）",
    "重要ポイント2（具体的・簡潔に）",
    "（5〜10項目を目安に列挙）"
  ]
}

【各フィールドの注意事項】
- transcription: 音声を省略なく正確に書き起こすこと。無音・雑音は除いてよい。
- summary: 必ず改行文字 \n で区切られた3文で構成すること。1文が長くなりすぎないよう注意。
- keyPoints: 各要素は1文で完結させること。5〜10項目が目標。

【言語】
すべての出力を日本語で行うこと。音声が日本語以外の場合も、日本語に翻訳して出力すること。
````

## 2. 設計の判断根拠

### 2.1 JSON出力の強制（二重戦略）

JSON形式で確実に返させるために、2つのアプローチを組み合わせています。

| アプローチ | 内容 | 役割 |
|-----------|------|------|
| **API設定** | `generationConfig.responseMimeType: "application/json"` | モデルレベルでJSON出力を強制。最も信頼性が高い |
| **プロンプト指示** | 「JSONオブジェクトのみを出力」「前後の説明文は含めない」 | APIの機能が効かない場合の保険 |

> `responseMimeType: "application/json"` を設定するだけで、モデルはマークダウンコードブロックを  
> 付けずにJSON本体のみを返すようになります。プロンプト指示は二重の保険です。

### 2.2 ペルソナの設定

```
あなたは大学講義の音声を分析する専門AIです。
```

**理由:** ペルソナを設定することで、モデルが「学術的な文脈で音声を分析する」という役割を明確に認識し、  
一般的な会話応答ではなく専門的な分析モードで動作するよう誘導しています。

### 2.3 講義名の動的挿入

```javascript
const titleLine = lectureName ? `講義名: 「${lectureName}」` : "講義名: 不明";
```

**理由:** 講義名を含めることで、モデルが専門用語や文脈を正しく解釈しやすくなります。  
例：「機械学習入門」と分かれば「ML」「過学習」などの略語を適切に扱えます。

### 2.4 `summary` のフォーマット指定

```
"summary": "1文目：講義全体の主題。\n2文目：最も重要な概念。\n3文目：結論や次回への展望。"
```

各文の**役割**を明示的に番号付きで指定しています。

**理由:** 役割を指定しないと、3行全てが似たような内容になったり、  
1文だけになったりすることがあります。「1文目・2文目・3文目の役割」を定義することで、  
情報密度の高い要約が得られます。

### 2.5 `keyPoints` の数量指定

```
5〜10項目を目安に列挙
```

**理由:** 上限なしにすると過多になり、下限なしにすると重要事項が抜ける場合があります。  
「5〜10」という範囲を示すことで、適切な粒度の要点が得られます。

### 2.6 `transcription` の「省略しない」指示

```
音声を省略なく正確に書き起こすこと。
```

**理由:** モデルは長い音声を「...（省略）...」などで短縮しようとする傾向があります。  
明示的に「省略しない」と指示することで、完全な文字起こしが得られます。

### 2.7 言語指定

```
すべての出力を日本語で行うこと。音声が日本語以外の場合も、日本語に翻訳して出力すること。
```

**理由:** 英語の講義音声を入力した場合、モデルはデフォルトで英語で返す傾向があります。  
日本語ユーザー向けのアプリなので、入力言語に関わらず日本語出力を強制しています。

## 3. プロンプト設計の反復履歴

### バージョン 1.0（フェーズ3設計時点）

```
以下の講義音声を分析し、必ず下記のJSON形式のみで回答してください。前後に説明文は不要です。
{
  "transcription": "音声の文字起こし全文",
  "summary": "講義内容の3行要約（改行区切り）",
  "keyPoints": ["重要ポイント1", "重要ポイント2", ...]
}
講義名: ${lectureName || "不明"}
言語: 日本語で回答すること
```

**問題点:** summaryの「3行要約（改行区切り）」という指示だけでは、  
モデルによって1段落になったり、箇条書きになったりと出力が安定しませんでした。

### バージョン 1.1（現行）

- ペルソナを先頭に追加
- summaryに「1文目・2文目・3文目の役割」を明示
- keyPointsに「5〜10項目」という数量レンジを追加
- 「省略しないこと」「絶対に含めないでください」などの強調表現を追加

## 4. カスタマイズガイド

### 出力言語を英語に変えたい場合

`_buildPrompt()` の末尾の言語指定を変更します：

```javascript
// 変更前
すべての出力を日本語で行うこと。

// 変更後
Please provide all outputs in English.
```

### 要点の数を変えたい場合

`keyPoints` の説明部分を変更します：

```javascript
// 変更前（5〜10項目）
"（5〜10項目を目安に列挙）"

// 変更後（3〜5項目に絞る場合）
"（最重要事項を3〜5項目に絞って列挙）"
```

### 要約の構成を変えたい場合

`summary` のフォーマット説明を変更します：

```javascript
// 変更前（3行）
"1文目：講義全体の主題。\\n2文目：最も重要な概念。\\n3文目：結論や次回への展望。"

// 変更後（5行に増やす場合）
"各文を \\n で区切り、以下の順に5文で記述：主題・背景・中心概念・応用例・結論"
```

### タイムスタンプ付き文字起こしが欲しい場合

`transcription` の指示を変更します：

```javascript
// 変更後
"transcription": "音声を書き起こし、各段落の先頭に [MM:SS] 形式のタイムスタンプを付けること。"
```

## 5. トークン消費量の目安

| 音声の長さ | 音声トークン数 | プロンプトトークン数 | 合計（目安） |
|-----------|-------------|------------------|------------|
| 1分 | 約 1,920 | 約 500 | 約 2,400 |
| 10分 | 約 19,200 | 約 500 | 約 19,700 |
| 30分 | 約 57,600 | 約 500 | 約 58,100 |
| 60分 | 約 115,200 | 約 500 | 約 115,700 |

> 計算式: 音声1秒 = 32トークン（公式ドキュメントより）  
> 出力トークンは文字起こし量に依存するため上記には含まれていません。

## 6. 既知の制限と回避策

| 制限 | 現象 | 現在の回避策 |
|------|------|------------|
| 長い音声での文字起こし省略 | 「...（省略）...」が入る | プロンプトに「省略しないこと」を明記 |
| コードブロック付きJSON | ````json ... ```` が付く | `_parseJson()` でフォールバック除去 |
| 要約が1文になる | 3文指定を無視する場合がある | 各文の役割を番号付きで明示 |
| 英語音声を英語で返す | 言語指示を無視する場合がある | 「絶対に」という強調表現を使用 |
| keyPointsが多すぎる | 20項目以上になる場合がある | 「5〜10項目を目安」と範囲を指定 |
